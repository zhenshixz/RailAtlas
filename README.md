# RailAtlas · 中国铁路地图

日间风格的 React + Leaflet 中国铁路出游地图。选择出发站与乘车时间上限，按 12306 真实经停时刻计算直达目的站：同一目的站多个车次取站到站时长的中位数。支持省市/站名搜索、时间或车次排序、收藏、各车次时长与经停查看、省名和省界，以及真实铁路背景。

## 出游规划

1. 在左侧搜索或点击地图上的站点，设为出发站。
2. 选择时间上限（默认 2 小时，也可自定义）。目的地列表与地图会显示中位乘车时长不超过该上限的车站。
3. 点击目的地查看最快/最慢时间、全部已读取的直达车次；点击一趟车查看从出发站到目的站的经停。
4. 「查看可达范围」「定位出发站」「定位目的地」才会主动移动地图，普通选中保留当前视野。

计算只使用同一趟 G/D/C 列车在出发站之后的经停，不推算换乘，不以车次始发终到的总时长代替区间时长。时长为出发站发车到目的站到站，包含途中停站，依据官方跨日信息处理午夜。重复服务记录去重后，每趟车权重相同；偶数个车次取中间两项的平均值。筛选按精确中位数，显示时间四舍五入到分钟，所以部分符合条件的目的站仍可能有实际用时更长的车次，详情会标出。

页面明确显示时刻参考日期。当前快照未读完时，结果和中位数可能变化，未查到记录不代表没有直达服务。缺少可信坐标的目的站保留在右侧列表。这里的时长不含到景区/市区的交通，也不表示车票有余票。

## 启动

双击 **`start.bat`**。需要 Node.js 22.12+ 和 Python 3.9+，首次会安装前端依赖；后续自动检查后台语法、构建前端并启动服务。失败时保留窗口和错误信息。

- 本机：<http://127.0.0.1:8790>
- 局域网：启动窗口会显示本机实际 IPv4 地址。其他设备与电脑连接同一网络后访问该地址。Windows 防火墙首次提示时允许私人网络访问。
- 保持启动窗口打开；Ctrl+C 停止服务器。端口冲突时可运行 `python server.py --port 8791`。

已有 `dist/` 时，也可以直接执行 `python server.py`，无需重新构建。

## 真实数据与完整性

本项目不是 12306 官方产品。访问的是官网公开的查询接口，没有获得铁路内部接口授权；不处理登录、验证码、抢票或购票。站名、电报码、车次始发/终到与已经读取的经停记录来自 12306；地图坐标与实际轨道是公开地理数据补充。

**不能把“已取得的数据”解释为全国全部数据已经完整。** 页面「数据来源」显示参考日期、官方搜索覆盖、已取得经停的车次数、已核实车站数、可落点数和缺失坐标，并可导出清单。当天未开行、未被官方公开接口返回、同步失败或尚未取得经停的车次不会被补造。12306 范围不包含台湾铁路，但地图边界保留港澳台和南海诸岛。

车站类型来自所选日期的官方车次始发/终到或经停记录，不根据站名中的“东/南/西/北”猜测。出发站目录仅列出已核实 G/D/C 车次服务的车站。缺少可信坐标的站仍保留在搜索目录和目的地列表；不会使用城市中心代替站址。

两个线路图层含义不同：

- **铁路实际轨道**：OpenStreetMap 的真实几何，包含普速和高铁，不能理解为全部轨道都办理 G/D/C。当前离线数据包标注构建日期 2026-09-02，按中国省级边界裁剪。原始数据可能有遗漏，部分小几何段在边界裁剪后不展示。
- **选中直达车次虚线**：从当前出发站到目的站的相邻经停站之间的直线示意，仅表示经停顺序，不表示铁路实际走向；没有坐标的中间站不会被跨越连线。

收藏仅存储在浏览器。车票、开行和出行信息以 12306 与车站公告为准。

## 更新数据

双击 **`sync-data.bat`**，输入 `YYYY-MM-DD`，留空使用北京时间当天日期；或在本机打开网站「数据来源」点击「同步数据」。局域网访客可浏览，不能启动后台同步。

```powershell
python scripts/sync_data.py --date 2026-10-06 --workers 4
```

第一次需要分段搜索车次，再逐车次查询经停，可能较久。每个成功响应写入 `data/raw/日期/`，可中断后再次运行续传；前端每 7 秒检查进度。优先读取不同起终点的长途车次，尽早扩展车站覆盖。重复上游失败时停止请求并保留快照，不绕过官方验证。一次只运行一个同步任务。

后台仅使用 Python 标准库即可运行。环境已安装 `requests` 时可复用 HTTPS 连接；否则自动使用 `urllib`。保留 TLS 校验；兼容 Windows Internet Settings 中本机 HTTP CONNECT 代理被误标为 HTTPS 的配置。直接运行脚本时确保网络/代理可连接 12306。

## 地理数据来源与重建

- 12306 站名录：<https://kyfw.12306.cn/otn/resources/js/framework/station_name.js>
- 12306 车次搜索：<https://search.12306.cn/search/v1/train/search>
- 12306 经停查询：<https://kyfw.12306.cn/otn/queryTrainInfo/query>
- 社区车站 WGS84 坐标：[China-rail-way-stations-data](https://github.com/listenzcc/China-rail-way-stations-data)，原始年代较早，以具体站点的来源为准。
- OSM 坐标与铁路几何：[@railroute-ts/china](https://github.com/mayurrawte/railroutes/tree/main/packages/china)，版本锁在 `package-lock.json`，数据遵循 [ODbL 1.0](https://www.openstreetmap.org/copyright)。英文站名规范化后与 12306 拼音精确匹配；存在多个相距较远的同名候选时不采用。
- 缺失坐标补充：[Wikidata](https://www.wikidata.org/)，采用中国铁路车站（排除地铁站）的中文名称精确匹配；同名多个条目时不采用。每个站点保留具体实体来源链接，数据遵循 CC0。下载脚本 `python scripts/fetch-wikidata.py`。
- DataV 中国省级边界：[地图选择器](https://datav.aliyun.com/portal/school/atlas/area_selector)。

`data/coordinate-overrides.json` 保留已核对的同名/同音坐标纠错及具体来源，优先于拼音匹配结果。例如福建长乐站与山东昌乐站拼音均为 Changle，福建长乐采用其独立 Wikidata 条目的公开坐标，避免可达范围被误拉到山东。

离线 OSM 数据可重新生成：

```powershell
node scripts/prepare-geography.mjs
```

生成 `data/rails.geojson` 和 `data/osm-matched-stations.json`；再次同步数据时会应用新增坐标。`scripts/fetch_geography.py` 可从公开 Overpass 服务补充原始车站和高速轨道；服务超时时继续使用已有离线数据。地图底图与已有数据在离线时可以浏览，实时查询及更新需要联网。

缺失坐标还可补充 `python scripts/fetch-wikidata.py`，然后运行 `node scripts/prepare-geography.mjs` 为新增坐标补充省份，再同步刷新快照。

## 开发

手机与小屏平板（宽度不超过 800px）使用全宽地图，底部提供出发站/时长、可达地图、目的地三个入口。搜索、筛选和车次详情在可收起的底部面板操作，适配横屏及手机安全区；输入框使用 16px 字体，地图站点扩大触控范围。桌面仍保留左侧设置、右侧目的地布局。手机样式独立放在 `src/mobile.css`。

```powershell
npm install
python server.py
npm run dev
```

Vite 开发端口默认 5173，API 代理到 8790。生产构建 `npm run build`，生产启动 `npm start`。启动 BAT 的非交互语法/环境检查：`cmd /c start.bat --check`。

主要文件：`src/PlannerApp.jsx` 出游规划交互；`src/planner.js` 直达、中位数和跨日计算；`src/ChinaMap.jsx` 地图；`src/station-layer.js` 按视野绘制站点与名称的 Canvas；`src/planner.css` 规划布局；`server.py` 本机/LAN 服务与官方查询代理；`scripts/sync_data.py` 数据同步；`data/atlas.json` 可审计快照。项目不依赖其他工作区项目即可启动。核心时间计算验证：`npm run test:planner`。

服务启动后会自动补齐缺失经停，按 1 分钟、5 分钟、15 分钟、1 小时、3 小时、6 小时退避重试，状态保存在 `data/repair-status.json`，重启后保留等待时间。仅请求未取得的车次；官方空响应仍保留为缺失。目录站数与完整经停详情冲突时，核对始终点、站序及有效时间后采用官方详情，并记录 `stopCountConflicts` 审计。关闭网页不影响后台补齐，服务需保持运行。

坐标匹配先采用中文站名对应的社区/Wikidata记录，再补充唯一拼音OSM记录；12306目录存在同音站名时禁止仅凭拼音定位。已核实的双洋（SQS）及杨源（AYS）均为福建车站，原始依据和纠错说明保存在 `data/coordinate-overrides.json`（杨源OSM原始响应：`data/raw/yangyuan-osm.json`）。不确定坐标的站点保留在目的地列表，不放置到推测位置。

手机目的地面板优先展示站点列表：标题和筛选入口合并为一行，分页保持约 29px 的单行高度；每页数量和范围放入浮层，展开不挤占列表。新增手机功能应区分常用操作和次要设置，避免常驻多行说明或重复标题。桌面分页仍保留总数、每页数量与后续结果提示。
